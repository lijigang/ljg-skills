# ljg-map · 形式化思考地图

用《学习观》关于概念、判别模型和联结模型的理解，看到文稿背后的知识结构：哪些词有明确的所指，现实对象凭什么归入它们，概念之间的关系在什么条件下成立。把看到的结构画出来，形式化负责减少歧义，白话和实例负责让关系可理解、可使用。

| 请求 | 执行 |
|---|---|

## Gotchas

- **知识观是洞察视角，图形由材料决定。** 具象、概念与应用的对应帮助检查知识是否接通，不构成固定的三个图层、三个栏目或必经步骤。分类交叉就画交叉关系，反馈就画循环；材料确有层级时才画层级。
- **节点来自当前文稿。** 不把任何文章都画成「经验—抽象—概念—记忆—学习」；只有文章本身讨论这些概念时，它们才成为内容节点。判别、验证可以写在边或节点解释里，无须一律占框。
- **地图不是换成公式的长文。** 成品先让读者看见承重关系，再解释图里的节点。不能只给概念清单、长表格或一串没有地图的公式。
- **形式化不以符号数量计。** 优先「中文名称 + 短公式」。定义符号后再使用，不另造一套图论元语言来描述本来很简单的文章。
- **分类与预测分开。** 「有圆圈」可以定义一类；「这一类会加分」是另一条需要依据的关系。满足分类条件不自动证明预测成立，也不能推出反面类别有反面结果。
- **箭头有语义。** 定义、归类、计算、相关、因果、类比、推断和反馈不能混作一种关系；用短边标签和必要条件区分。猜想仍标猜想。
- **图的完整不能靠编造。** 文稿缺少判别标准、实例或验证办法，就在对应位置标缺口。补充的教学例子、应用设想与可行性判断要与原文陈述分清。

## 成品约定

默认直接在对话中交付 Markdown、Mermaid 和可读公式。用户要求保存、特定格式或修改已有产物时，按其指定交付；本技能不默认写笔记、覆盖原文或发布。

主图显出这篇文稿特有的知识关系，不预设层数、形状或统一应用流程。主要关系保持易读，次要分支可以放到有连接位置的补图或标记表。每个图中节点均能在解释中找到相同编号或名称，以及定义、公式、语义和具体对应。

## Examples

- `/ljg-map <文稿或文件路径>`：读到实际内容后，画出该文稿的知识结构，解释每个节点，用合适的具体对应讲清关键关系。
- `把这篇文章的概念、判别和联结画清楚，别改写文章`：保留作者的主要推理、并列结构及重要分歧；在箭头处标明条件和来源中的不确定性。
- `这张图太难懂，重新画`：减少符号和主图拥挤度，用一个合适例子贯穿；保留会改变判断的条件，不以删掉论点换取表面简洁。
