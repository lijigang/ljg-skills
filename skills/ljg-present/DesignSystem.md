# Unix Editorial · 设计系统

## 设计基因

借鉴编辑式演示的构图纪律：先决定观众这一页要看见什么，再选择承载它的文字尺度和图形关系。整套一致性由稳定网格、字体职责、标记规则与页面节奏产生。

ljg-present 的身份是「可投影的 Unix 手册」。巨句像清晰的输出，流程像管道，表格像排整齐的数据，图表像可以直接读懂的证据。Unix 气质落实在对齐和信息密度；不把 shell prompt、路径名、状态栏或窗口外壳贴在无关内容上。

从参考风格吸收：一页一判断、有限版式、留白张力、强调克制、图表标注贴近对象、整套缩略图验收。中文竖排、章节插画、黑签、双语页脚属于参考自身的语言；本系统使用横排大字、等宽刻度、细规则线和单点信号形成辨识度。

## 舞台与字体

横屏 16:9 是主要演讲场景，以 `1920×1080` 看构图，并在 `1098×648` 验证后排可读性。页面充满视口，不拉伸文字；手机单列重排。外部主块共用左右边界，局部对齐服从内容：巨句居中，证据对齐，流程沿方向，比较沿共同基线。

| 职责 | 处理 |
|---|---|
| 中文主叙事 | Source Han Sans CN / SC（思源黑体）优先，PingFang / Microsoft YaHei 回退；字重 500–700 |
| 英文、代码、数值 | 内嵌 IBM Plex Mono Regular / Bold；数值 tabular-nums，关闭编程连字，字符形态保持清楚 |
| 巨句 / 封面 | 大字与留白，不再叠大图或装饰框 |
| Chart 主张 | 左对齐，约正文标签的 1.4–1.7 倍；短到一眼可读 |
| 图内标注 | 紧邻对象，横屏有效字号 ≥26px，竖屏 ≥16px |
| 页码 / meta | 等宽、小、低层级；meta 只出现在封面 |

IBM Plex Mono 的两种字重由 Tools/EmbedAssets.ts 以 data:font/ttf;base64 嵌入，HTML 同时保留 OFL 许可。中文思源黑体未内嵌时由接收机器的中文字体回退，不能声称所有设备中文字体完全一致。需要精确复现中文时，只嵌入有许可的字体子集并重新检查体积。不把中文强制拉宽或换成像素字。

## 配色与强调

| Token | Dark | Light |
|---|---|---|
| 背景 | `#18191C` | `#F2F0EB` |
| 封面 / 章节 | `#101113` | `#18191C` |
| 正文 | `#E8E5DF` | `#18191C` |
| 次级文字 | `#99958E` | 正文色，靠字号降级 |
| 重点文字 / 数据 | `#D7AF74` | `#825B25` |
| 暗场局部标记 | `#D7AF74` | `#D7AF74` |

石墨底保持中性，暖白承担正文，琥珀只给重点：Unix 气质由字形和信息秩序支撑。正文在 dark 的对比度 ≥9:1。浅底重点使用较深的琥珀色，避免浅琥珀小字。背景是纯色平面，去掉网格、扫描线、径向氛围和光晕。表格只保留必要横线，代码可以有一个硬边暗面板。

每页先用尺度建立一个焦点，再用一种方式强调必要部分。普通页强调范围宜控制在正文约 12% 内；源文自带更大范围的强调不删字，可降低视觉强度。Chart 最多一个对象用琥珀信号色，其他对象以正文色、空心点或位置区分。整组同色会丢失重点。

## 构图如何选择

- **判断**：一个文字焦点；短句完整单行，长句按源句界续页。
- **递进**：同层 3–4 项作为一个组，单列、细线与垂直间距；不用卡片海。
- **比较**：两个对象共享维度，左右并置；手机按源顺序上下读。只有确实存在两方比较才启用双栏。
- **数量**：条形长度回答「差多少」；必须有共同零点和单位。
- **趋势**：点与直线回答「怎样变化」；按真实 x 距离放点，不平滑，不补未知值。
- **流程**：2–4 个明确有序节点；连接线回答「下一步是什么」。箭头表达源中已有的方向。
- **证据**：表格保留结构，代码保留空格；无需再套一个模拟终端窗口。

同一页标题和图表共同完成一个动作。标题约占可用高的 15–25%，关系主体占 50–65%，余下交给留白与必要注记。留白过多先判断内容是否已经完整；不以补图填空。

## 字符图的线条语言

新生成的字符图默认用 Unicode：细线 `─ │`，转角 `┌ ┐ └ ┘`，连接 `├ ┤ ┬ ┴ ┼`，方向 `→ ← ↑ ↓`。同一图保持一致的线宽；需要柔和转角时可用 `╭ ╮ ╰ ╯`。不用 `+---+`、`|...|` 或 `-->` 拼接新图的轮廓和箭头，不混搭粗线、双线、阴影字符或 emoji。

节点是否需要框由关系决定；一条清楚的线足以表达时，不给每个词套框。数值精度、真实坐标和复杂比较继续交给原生 Chart，不为了 Unicode 风格把定量图变成不准确的字符画。

字符图在 `pre` 中渲染，保留换行与空格；带线框字符时用紧接的行高、等宽字体、零字距和常规字重。中文通常不是一个拉丁字符宽度，不靠字符串长度猜列宽。实际浏览器检查交点相接、纵线连续、箭头朝向、中文标签和缺字方框；字体回退导致错位时，调整生成图布局或内嵌覆盖所需字符的许可字体，不自动退回 ASCII。

源文已有的 ASCII/Unicode 图与代码保持原样。这个偏好决定新图如何画，不授权重写原稿；用户明确要求转换旧图时再作等义重绘。

## 整套节奏

`封面 → 章节 → 判断 → 证据/关系 → 判断 → 下一章` 是常见节奏，不是固定页序。真实顺序由作者 outline 决定。密集证据前后如果原稿已有短句，用尺度形成呼吸；不擅自编写转场页、章节数或收束金句。

七种角色是有限语法。同类页保持一致；不同内容以各自结构形成变化。不要随机换左右轴，也不要因「全部居中」而把图表标签、代码和数值对齐破坏。

## 视觉验收

以整套 25% 缩略图检查：能否立即看出每页的单一焦点，连续页面是否拥有同一种视觉语言，密集与稀疏是否来自内容的差异。然后放大检查最密页与每种角色：

- 字形真实可读，孤字、标签碰撞、正文/页脚重叠为失败。
- 文字与图形关系成立；删除一条线若没有损失信息，那条线通常可以删除。
- 重点标记是否在说同一种「此处重点」；不再引入多套颜色创造未说明的语义。
- 条形零点一致；折线间距真实；图表可见值与源数据一致。
- 手机的比较/流程顺序、折线数据读法成立；不把整个桌面缩成缩略图。

审美依据是实际页面。代码中有 token、validator 通过或作者觉得「极简」，各自都不能代替观察。
