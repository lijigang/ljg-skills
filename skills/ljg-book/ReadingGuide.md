# 阅读与写作指南

这份指南帮助判断材料够不够、全书哪些内容不能漏，以及怎样把它们讲给没读过的人。成品要求和复述检查以 `SKILL.md` 为准。

## 材料够不够

在 `references/coverage-map.md` 中如实记录：

- **完整拆书**：全文或等价材料足以追踪全书的问题、主要内容、解释与适用范围。
- **初拆**：只有目录、样章、访谈、可靠评论或旧笔记，只能形成局部理解。
- **假设版**：资料更少，只能提出明确标为暂定的判断。

还要判断材料能否说明：人最初怎样理解，哪件事让这种理解需要补充，作者增加了什么，最后怎样重新看原来的问题。有摩托车、手机或实验这类具体名词，并不意味着这些过程已经有据可查。

材料不足，就继续找原文；找不到，便明确只解释已有材料支持的部分。不要为了写得生动，补出原文没有的动作、天气、零件、对话、表情或心理。文学、哲学与叙事作品同样如此。

## 读全书时保留什么

完整拆书需要四类证据：

1. 作者为什么处理这个问题，最初的处境或困惑是什么。
2. 什么事实、事件或后果让原来的理解需要补充。
3. 作者怎样增加关系、条件或新的看法，改变原来的解释。
4. 最后形成什么判断或局面，哪些问题仍未解决，结论适用到哪里。

最初的人物关系和基本区分，也要在材料中找到依据。随后列出至少 5 项候选内容，记录位置、作用、相互联系，以及删去后会缺少什么。复杂或篇幅大的书按需要增加，不设上限。候选材料用于决定取舍，不直接充当正文目录。

## 先认清这本书，再选贯穿文章的问题

先用日常话写清：

- 这是什么类型的书，具体围绕谁、什么对象或什么问题展开；
- 从哪里开始，经历哪些主要变化，最后在哪里结束；
- 哪些主线不能省，它们为什么写在同一本书里；
- 哪些具体人物、事件或论述必须出现在成品中。

最后一项使用能在正文中精确找到的短语。完整拆书至少 3 个，按需要增加；初拆或假设版至少 1 个，且有实际材料支持。不能用「问题、关系、变化、结论」这些通用词代替。

再选择一个普通人容易理解的问题，帮助组织内容。例如：

- 问题这么严重，为什么这个解决办法还没有被证明有效？
- 照着手册做，为什么仍然修不好这台机器？
- 同样的数字换一种说法，人的选择为什么变了？
- 小范围有效的规则，为什么扩大以后反而制造故障？

选一个贯穿全文的问题时，也要保留原书的重要内容。读者既要能顺着问题读下去，也要知道这本书具体写了什么。若说完「自由、质量、未知、成长」以后，原书的人物、事件和结尾都可以删掉，就还没有讲清这本书。

## 同一种关系怎样解释不同内容

有些书反复用同一种关系解释不同现象。理论书可能依靠函数或因果机制，历史书可能说明相似条件下反复出现的因果关系，传记可能呈现选择怎样影响后果和下一次选择，文学可能让同一个矛盾逐渐显出不同含义。

贯穿文章的问题帮助读者继续读；书中反复起作用的关系则帮助读者理解后面的内容。两者要分清。几个案例都谈自由，还不足以说明它们为什么写在一起；需要说明它们呈现了同一种因果关系，还是让同一个矛盾变得更清楚。

若提出这样的共同解释，就检查它能否说明至少两处相隔较远的关键转折、帮助理解一个尚未讲过的相近情况，并指出哪里不再适用。做不到时，保留为局部发现，不把它当成全书的解释。没有共同解释的作品，在 coverage 如实写明，不强行归纳成公式。

理论书中，读懂后面的案例若依赖某个关系，通常应在前两个一级标题内用一个例子讲清：从什么条件开始，得到什么结果，为什么会这样。叙事作品需要逐渐揭示人物关系或保留悬念时，可以稍后再讲，在 coverage 说明理由。

正式模型要保持坐标、单位和结果方向一致。例如，「数值越大」究竟表示收益更多还是损失更多，不能悄悄改变。确实需要换一种表示时，先解释它怎样改变符号、方向或判断。

## 用什么让读者跟得上

按书的内容选择合适的具体事物或问题：

- 一次读者可以重新判断的选择；
- 一组可以代入的数字或公式；
- 一个能看清变化的日常物件或小任务；
- 原书人物正在面对的一个具体时刻；
- 不同年代反复出现的同一个问题；
- 一段持续变化的关系，或逐渐清楚的矛盾；
- 几次相互影响的选择与后果。

开头要容易理解，不用先学一整套背景。展开以后，让读者始终知道此刻在看什么、它与前面有什么联系。不必为了保持同一个物件而扭曲全书。

检查时，读者应能说出「原来怎样理解，哪件事让它需要改变，后来明白了什么」，也能说清书中具体写了哪些经历或论述。只剩一个寓意，还需要补内容。

## 什么时候需要图表

理解依赖曲线、位置、顺序、层级或精确对应时，可以加入一个最小的图表，减少读者在脑中拼凑关系的负担。曲线、空间和层级用 ASCII 图，精确对应用表格，状态变化可以用流程或时间线。不为装饰加图，也不要求每本书都有图。

图后紧接一个具体例子：先在图上找到相关位置，再说明条件改变后，结果怎样变化。若读者只记住了图形，却说不出它解释了什么，图表还没有起到作用。图块不超过 80 显示列。

## 正文选哪些例子

研究时可以收集很多材料，正文只选讲清全书需要的人物、事件、比较或模型。每个例子都应当带来前面尚未讲清的东西，例如介绍一种关系、区分相近情况、反驳旧解释、补充条件，或帮助回应开头的问题。

每个例子都能用日常话说清：从什么处境开始，原来的判断为什么可信，发生了什么，理解怎样改变，什么仍未解决。关键例子要给读者停留的时间，其他材料可以简短交代；不必给每个例子分配同样篇幅，也不要求逐段提炼道理。作用重复就合并，重要主线仍须保留。

不要因为候选材料有五项，正文就机械安排五个例子。也不要把几个本来各需说明的关系塞进一段，以此显得内容齐全。

## 怎样写出一次理解的变化

「父亲会听机器的声响、检查原因，并根据反馈调整」概括了一段过程，却没有说明当时的问题在哪里。需要从材料里找到具体时刻，让读者先明白某个判断为什么合理、为什么值得尝试，再看到它解释不了什么。涉及人的选择时，还要留意原来的办法保护了什么愿望或顾虑，改变它为什么不容易。

可以用下面的顺序检查有没有跳过重要解释：

```text
进入一个具体处境
→ 明白原来的判断为什么可信或难以放下
→ 事实、事件或结果说明遗漏了什么
→ 加入需要的关系、条件或区分
→ 再看原来的处境，理解已经不同
→ 看清接下来还需要问什么
```

这只是帮助查找遗漏，不要求正文展示六个步骤。实际文章可以通过选择、比较、人物遭遇、制度变化、模型故障或逐渐加深的矛盾完成。不要刚写到人物就替他总结教训：允许一次尝试或一段犹疑继续发展。理解改变时，已经发生的事情未必改变；只有行动或条件确实变化并带来新后果，才写结果变了。

概念在读者感到需要以后出现。可以紧跟一个结果，也可以等两个例子比较以后再介绍。讲完概念，马上回到眼前的问题，说明它补上了什么，不停下来集中罗列定义。

## 段落之间怎样连接

让读者明白为什么讲完这一部分，需要接着看下一部分。联系可以来自尚未解决的问题、新条件下出现的变化、人物的后续选择，也可以来自必要的对照或同一意象的再次出现。人物的愿望与顾虑也能延续关切，不必在每一节末尾添加过渡问句。

例如，手机政策的论证可以依次追问：理由是否足以支持结论，需要什么证据补足，别的原因会不会解释同一结果。读者一直在检查「现在是否足以支持加重处罚」，就容易知道为什么要看下一份证据。

已有的人物、问题或模型仍然合适时，可以继续用。需要换场时，交代与前文的实际联系：模型扩大以后不再适用，人物进入另一段关系，同一制度在不同条件下出现不同结果。不必每次都制造「前一段解释失败」才允许继续。

写完以后，试着交换相邻小节，观察前提、对照和认识变化是否受影响。若只是几个案例并排摆放，找回它们共同说明的问题，并补清相互联系。若几个并列部分顺序可以调整，说明它们各自帮助理解什么、当前安排为什么合适即可；不能仅凭可换序就判定文章失败。

## 不同书怎样展开

| 书的类型 | 合适的讲法 | 需要避免 |
|---|---|---|
| 分析与理论 | 先形成判断，再用区分、反例或证据检查，回头看判断改变了哪一步 | 一开始就给出整套术语 |
| 方法与实践 | 比较旧做法和新做法的结果，也说明作者是否改变了「什么算有效」 | 没有结果，只列行动建议 |
| 技术与科学 | 用能手算、跟踪或预测的最小模型说明关系，再看规模、故障或适用范围 | 只给公式，不解释数字的含义 |
| 历史与社会 | 同一个问题进入不同年代和条件，说明结果为什么变化 | 只为凑齐年代而换场，或强守一个物件 |
| 传记与叙事 | 跟着选择、后果和后续选择，理解人物与关系的变化 | 把一生压成成功法则或即时反馈实验 |
| 文学与哲学 | 从有依据的处境、关系、意象或论证困境中，逐渐看见原先遗漏的部分 | 强迫人物找到办法，或替作品消除矛盾 |

## 证据与适用范围怎样写

证据在它能回答当前问题时进入。眼前需要查明的是问题是否存在、原因是否成立、办法是否有效，还是代价是否可接受，就先说明能回答这一项的证据，避免一次罗列所有证据类型。

原书材料、作者解释和自拟例子要分清：

- 原书材料决定结论有多少依据。
- 作者解释说明作者怎样理解这些材料。
- 自拟例子帮助读者理解关系。它依据什么、做了哪些简化、不能推出什么，完整记录在 coverage。

正文用「想象一下」「先拿十二根纸条」「把最后一句遮住」自然引入自拟例子，不让读者误以为原书发生过这件事。说明适用范围时，继续写它能解释什么，还需要哪些现实条件。

例如：

> 纸条能让你看见，连接方式为什么会改变受力。但要算钢梁能承受多少吨，还得考虑截面、缺陷和载荷。

不要在这里插入「讲解者依据旧稿构造」「本轮未核」之类资料核验和改稿说明。这里限制的是讲述中途交代制作过程；可以使用第一人称，也可以讲原书人物的写作经历。

## 读起来是否自然

按说给一个聪明朋友听的方式朗读正文。让一个念头有说完整的时间，一个发现有被体会的余地；读者已经明白时，可以停在事情上，不再重复解释。可以重复同一个普通词，不急着换同义词。

连续出现几个抽象名词，或一句话需要在脑中翻译一遍时，回到具体意思：谁做了什么，事情怎样变化，读者因此明白了什么。替换一个词仍不自然，就重新组织整句。

段落按思绪与事情的进展自然分开，长短句相互配合。不要让每段都遵循同样的「例子、结论、边界」节拍，也不用机械的短段制造阅读感。篇幅由需要说明和经历的内容决定，不设字数目标或上限。

沉浸感不靠给每个人物补心理。技术书可以靠读者真的想知道一个办法能否奏效，历史书可以靠局势如何变化吸引人；材料只支持概括时就概括。自拟情景清楚引入，原书人物当时的行动、后来反思与未实现的愿望分别处理，不把后见解释编成现场独白。

## 标题与结尾

标题写具体问题、事件、变化或结果，让人看得出内容怎样展开。最迟读完前两个一级标题，读者应当能认出书里的主要人物或问题、主要变化，以及相连的必要主线。

结尾回应开头，不再加入新术语。写清现在能怎样重新理解那件事、重做那次判断，或为什么原来的矛盾依然存在。若结尾可以直接放进任何一本书，就需要重新联系这本书的具体内容。

最后按 `SKILL.md` 的「末节：读完后留下什么」写收束段；格式和内容要求集中在那里，不另加一套栏目。

## 检查与保存

只给评估者最终成品，按 `SKILL.md` 的「只看成品，能否复述」回答四个整书问题和九个理解问题，再单独检查末节。不要提供 coverage、原书或预期答案。

书中若有共同的解释，还要用日常话说明它怎样解释两处相隔较远的关键变化、换到一个相近情况会怎样、哪里不再适用。随后逐一核对所选例子的起点、结果、作用与后续问题；有图表时，检查读者能否用图理解紧随其后的例子。

若只能复述术语或结论，就回到最早跳过事实和解释的地方补写。若内容之间没有实际联系，补足问题、对照或人物发展的关系，不能只添「接下来」「另一个例子」充当连接。

Markdown 使用 `references/template.md`。正文完成后补 `description`，保持 Denote 文件名与 `identifier` 一致。保存位置与命名规则见 `SKILL.md`。

运行：

```sh
bun {skill_dir}/scripts/validate_note.ts /absolute/path/to/note.md \
  --coverage /absolute/path/to/coverage-map.md
```

validator 检查材料记录、必填字段、正文中的原书具体短语、文件结构和部分难读的信号。它不能代替读者复述。

保存以后，用真实 Emacs 读回：确认 `denote-retrieve-filename-identifier` 与文件名一致，`denote-file-has-denoted-filename-p` 为真，文件出现在 `denote-directory-files` 与 consult-notes 中。现有 Emacs 服务不可用时，可以使用能加载本机 Denote、consult 与 consult-notes 的批处理 Emacs；验证器不可用时明确延期，不把未执行写成通过。
