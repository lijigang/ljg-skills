# Reading Guide：跟着一本书，把原来的看法走一遍

读者不需要先知道这本书的框架。他需要先遇到一件自己会判断的事。

让他照原来的想法判断一次。把结果写出来。然后让书里的事件、案例、论证或人物后果来检验它。哪里出了问题，作者就在改哪里。改完再回去看，新的结果会把人带进下一件事。

下面是后台工作顺序。写成文章以后，这些步骤全部藏起来。

## 先把材料边界放到后台

只给书名时，先找到足以支持判断的材料。给了 PDF、EPUB、正文、样章或旧笔记时，先读原文。

每次任务都复制 `references/coverage-map.md`，先填三项：

- **材料等级**：完整拆书、初拆或假设版。
- **主要材料**：实际读到的全文、样章、目录、访谈或可靠评论。
- **能支持到**：这些材料足以支持哪些判断，不能支持哪些判断。

三种等级的含义：

- **完整拆书**：有全文，或有足以追踪全书问题、做法、变化和边界的书内材料。
- **初拆**：只有目录、样章、访谈或可靠评论，可以形成局部理解。
- **假设版**：资料很薄，只能提出有标记的暂定判断。

这些信息不进入解读成品。证据不足时，直接缩小相应判断。比如只有样章，就写「这个样章显示……」，不要在文章末尾另放一份研究说明。

作者或出版社页面用来核对书名、版本和作者自述。外部评论只有在它会改变主线判断时才进入后台。研究的作用是防止说过头。

## 全文材料要走过整本书

材料等级为完整拆书时，把覆盖记录填完。先找四类证据：

1. 作者为什么非处理这个问题不可。
2. 作者怎样建立观察对象和基本区分。
3. 核心机制或做法怎样在材料上运行。
4. 最后形成了什么判断，结论停在哪里。

这个顺序只负责检查漏读，不负责安排文章。

再列 5 到 12 个候选部件。每项记录：

- 它在原书中的准确位置；
- 它解决了什么问题；
- 它与其他部件怎样连接；
- 删掉以后，读者还能不能理解作者最后形成的观看方式、判断、机制或张力。

方法型书最醒目的往往是最后一句结论，真正有用的却可能是前面那套观察和操作。文学作品最容易被摘成主题，真正推动理解的却可能是人物反复遇到同一个矛盾。若删掉中间变化只剩一句漂亮话，说明还没读懂。

## 先找一条贯穿全书的张力

一条张力，是全书反复碰到、却不能用旧答案一次解决的东西。

它可以是：

- 一种说法改变以后，人的选择为什么跟着改变；
- 一个看似有效的办法，为什么不断制造更大的问题；
- 同一种制度，为什么在不同条件下产生相反结果；
- 一个人为什么得到想要的东西以后，反而更不自由；
- 一个技术模型为什么在最小案例里成立，放大以后却失效。

写成一句能带出冲突的话。它越具体，越能帮助删材料。

不要用一个宽泛主题代替张力。「这本书讨论自由」太大。「一个人拥有更多选择以后，为什么仍然无法作出自己的决定」才会推动场景。

## 从最简单的场景开始

优先使用书里的案例、人物、实验、冲突或反常现象。它天然带着作者关心的条件，不容易讲偏。

没有合适的小案例时，可以做一个简化版本。保留那些一删掉就会改变结果的条件：时间顺序、反馈、资源限制、角色关系和判断标准。

一个好场景很简单：

```text
现在发生什么
    ↓
人自然会怎样理解
    ↓
他因此怎样选择或行动
    ↓
实际得到什么结果
```

读者最好能马上说：「如果是我，我也会这样想。」后面的变化才有重量。

别这样开头：

- 「这是一本关于……的重要著作。」
- 「某个领域长期存在争论。」
- 先介绍作者生平，再列全书要点。
- 先给核心术语，再找故事证明它。

这些写法让读者站在门外。具体场景让他先走进去。

## 看清第一次运行的结果

不要提前把读者的自然反应说成幼稚、错误或过时。让它真的运行一次：

```text
他看见什么
    ↓
他怎样理解
    ↓
他做了什么
    ↓
他期待什么
    ↓
实际发生什么
```

问题要落在结果上。两个东西分不清；同一选择前后翻转；办法眼前有效，却带来更大代价；人物得到了想要的东西，反而更远离自己。

这个结果必须来自原书。为了让故事好看而编一个作者没有面对的失败，会把整篇文章推向另一本不存在的书。

## 问清楚这一次到底改了什么

用四个后台变量检查：

- `x`：处境。谁和谁在什么时间、资源与关系里。
- `R`：理解。人怎样区分、命名和判断眼前的事。
- `f`：反应。人在这种理解下怎样选择、行动或停手。
- `E`：检验。什么结果算证据，什么变化足以推翻原判断。

旧理解得到结果以后，让书中的证据或事件施压。然后问：作者真正改的是哪一项？

有时作者给了一个新概念，改变 `R`。有时他换了实验或证据标准，改变 `E`。有时处境本身变了，原来正确的动作突然失效。方法书常直接改 `f`，但新做法仍要接受结果检验。

不要预设每一步都是「发现问题，再加入一个概念」。那会把历史写成术语列表，把小说写成方法课。

## 让结果长成下一场景

一次更新之后，马上重新运行。

如果结果已经不同，写清哪一件事先变了。这个新结果通常会带出下一场景：

- 参照点改变以后，原来的选择翻转了；接下来要问，谁决定参照点。
- 激励改变以后，个人行动变了；接下来要看，很多人同时行动会发生什么。
- 人物离开老师以后，摆脱了旧答案；接下来却要面对没有答案的生活。
- 简化模型解决了局部问题；扩大规模以后，新故障暴露出被忽略的反馈。

这就是回流：

```text
x_t → R_t → f_t → 结果
               ↑       ↓
          E_t 检验  暴露缺口
                       ↓
          更新 x / R / f / E
                       ↓
                  x_(t+1)
```

图只在后台帮助检查。成品直接讲发生了什么。

## 一个场景不够，就让张力带路

短案例可以从头走到底。历史、社会、技术和文学作品常需要多个场景。

换场景要有原因：前一个场景产生的结果，把问题推到了新的条件里。不是因为还想多覆盖几个章节。

多个场景可以这样连接：

- 同一个问题在不同条件下怎样变形；
- 同一个人物怎样反复遇到旧答案的边界；
- 同一种机制在不同对象上怎样得到相反结果；
- 同一个意象怎样随着经历改变含义；
- 同一技术模型怎样从最小情况走到边界情况。

只要张力没有换，读者就仍在想同一件事。

## 不同书型，顺着不同地方推进

### 分析和理论

重点通常在 `R` 或 `E`。让一个现象先按常识解释，再用书中的区分、反例或证据标准改写理解。不要只复述结论，要让读者看见为什么旧解释不够。

### 方法和实践

重点通常在 `f`。让旧做法得到真实结果，再运行新做法。若作者改变了「什么算有效」，`E` 也要一起写出来。没有结果检验的方法，只是建议清单。

### 历史和社会

同一张力穿过多个 `x`。人物、制度和时期可以变化，核心问题保持不变。每个场景都要让前一个判断更精确，不能排成年代摘要。

### 技术和科学

从最小可运行模型开始。先让简单解释工作，再用故障、边界或反例逼出下一层机制。保留真正改变结论的公式和结构，下一句说清它在人话里意味着什么。

### 文学和哲学

人物经历、关系变化、意象反复或论证困境都可以推动 `x` 与 `R`。结尾不必给方法。它可以让一个人重新命名经验，也可以让原本被遮住的矛盾终于无法忽略。

## 走到这本书真正形成的东西

别在术语解释完以后停下。继续问：这些变化连起来，作者最终形成了什么？

答案可能是：

- 一种新的判断标准；
- 一条可以运行和检验的机制；
- 一种看待某类经验的方式；
- 一项行动或克制的改变；
- 一个无法被简单解决、但现在能被准确看见的矛盾。

做两次边界检查：

1. 改变一个关键条件，结果最先在哪里变化？
2. 找一个表面相似、关键条件不同的情况，当前解释还能不能区分？

条件怎么改都不变的结论，多半只是口号。相近情况完全分不开，说明关系还没讲清。

## 最后回到开头

返程时不再加入新东西。回到最初的人或处境，只回答：同一件事现在为什么不能照旧理解？

变化可以落在：

- **看见**：过去漏掉什么，现在会注意什么。
- **判断**：过去比较什么，现在换成什么标准。
- **提问**：过去先问什么，现在先问什么。
- **行动**：过去按什么顺序做，现在改了哪一步。
- **克制**：过去会立刻做什么，现在为什么先停一下。
- **容纳**：过去急着消掉什么矛盾，现在为什么允许它留下。

若删掉这本书以后，返程仍像一句放到哪里都对的建议，它就写得太泛。

## 证据跟着变化走

每次转折都要能回到原书：一个场景、实验、人物变化、关键区分、作者推论或反例。

相应判断出现后，紧接着说明：

- 原书直接给了什么；
- 作者怎样解释它；
- 哪一小步是为了讲清而做的推演；
- 这条证据最多能支持到哪里。

数字只留会改变理解的。留下以后，立刻翻译它说明什么。

## 只有关系看不见时才画图

先问读者卡在哪里：关系看不见，还是证据不相信？只有前一种适合画图。

| 思想形状 | 更省力的表达 |
|---|---|
| 前后步骤、因果传导、状态变化 | 流程图或时间轴 |
| 循环、反馈、自我强化 | 回路图 |
| 层级、部分与整体 | 结构图 |
| 分布、边际变化、空间关系 | ASCII 曲线 |
| 两种机制反复对照 | 小表格 |
| 同一个场景多次变化 | 对齐的过程记录 |
| 两三句话已经足够 | 纯文字 |

图放在关系已经用例子讲明白以后。ASCII 图使用 Org 的 `#+begin_example` / `#+end_example`，宽度不超过 80 字符。一张足够。

## 按事情的变化命名文章

顶层标题写事件、变化或条件。它们的作用是让读者看见事情在往前走，不是把内部步骤翻译成漂亮说法。

分析类书可能长成：

```text
为什么换一种说法，选择就翻了
人先站在哪里，再看得到失
同一决定怎样重新问一遍
```

文学作品可能长成：

```text
老师给的答案为什么进不了生活
河流怎样把矛盾放在一起
回到老师面前，他还需要答案吗
```

一本书可以有两个标题，也可以有更多。前后没有真实变化，就不要换标题。场景已经跨过一个重要门槛，就不要为了凑固定数量把它们挤在一起。

全文写完后再补 `#+DESCRIPTION`。用一两句写清这本书让哪种旧看法发生了什么变化。它服务检索，不在正文里重复一遍。

## 写作声音

- 用日常中文。先写人、物、动作和结果，再写概念。
- 一段只做一件事。条件、机制和边界太多就拆开。
- 短句为主，但句子完整，主语清楚。
- 直接写事情怎样发生。少写「作者认为」「提供了一种可能性」。
- 过渡来自内容变化，不按「首先、其次、最后」轮流报幕。
- 术语先讲作用，出现后立刻放回场景。
- 类比要保持角色、方向和结果一致，对不上就不用。
- 结论直接说，边界贴着结论。
- 标题不编号，不显示 x、R、f、E 等内部标签。

## 自查

- 后台记录是否写明真实材料、等级与支持边界？
- 完整拆书是否走过全书四类证据，而不是只找到醒目结论？
- 是否找到一条足以筛选材料的贯穿张力？
- 开头是否是一件读者马上能想象的事？
- 原有理解或反应是否真的运行，并产生具体结果？
- 每次缺口是否来自原书，而不是为了故事现编？
- 是否判断清楚 x、R、f、E 中真正被改写的那一项？
- 更新后的结果是否自然产生下一场景？
- 多个场景是否仍由同一条张力连接？
- 结尾是否形成判断、机制、观看方式或准确的未决张力，而不是停在术语？
- 是否能区分一个相近场景，并说明关键条件改变后哪里先变？
- 证据、作者解释和讲解者推演是否分清？
- 返程是否回到开头，写出这本书独有的变化？
- 顶层标题是否来自具体内容，没有暴露内部分析步骤？
- 解读成品是否只保留读者需要的内容，没有研究工作台？
