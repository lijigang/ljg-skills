# Reading Guide：后台读全，前台一次只让一件事发生

这份指南负责研究与取舍。成品不是覆盖记录的翻译，而是一条普通读者能够亲自运行的理解路径。

## 先锁材料边界

每次任务复制 `references/coverage-map.md`，记录材料等级、实际来源和支持边界。

- **完整拆书**：全文或等价材料足以追踪全书问题、对象、机制与边界。
- **初拆**：只有目录、样章、访谈、可靠评论或旧笔记，只能形成局部理解。
- **假设版**：资料更薄，只能提出有标记的暂定判断。

再回答“材料能否支撑具体运行”。判断标准不是有没有摩托车、手机、实验这类名词，而是有没有一段可以按先后还原的材料：人物或读者先知道什么，怎样判断或行动，发生什么结果，结果怎样改变判断。

如果不能，不要把泛化概括写成现场。继续找原文；找不到就缩小输出，明确只解释材料支持的局部。证据边界高于叙事感染力。

## 全文材料怎样读

完整拆书先覆盖四类证据：

1. 作者为什么非处理这个问题不可。
2. 作者怎样建立观察对象和基本区分。
3. 核心机制、做法或人物变化怎样运行。
4. 最后形成什么判断，在哪些条件前停下。

再列 5–12 个候选部件，记录位置、作用、连接关系和删除测试。它们帮助判断什么不能漏，却不直接决定正文目录。

研究完成后，把全书压成一个普通人真的会问的问题。好的问题带着可预测的冲突，例如：

- 既然问题这么严重，为什么这个解决办法还没有被证明？
- 照着手册做为什么仍然修不好眼前这台机器？
- 同样的数字只换一种说法，人的选择为什么翻了？
- 规则在小范围有效，放大以后为什么反而制造故障？

“这本书讨论自由、质量、决策”不是读者问题，只是主题标签。

## 找到最小可运行对象

一个好入口不一定是故事。它可能是：

- 一次读者可以立即重做的选择；
- 一组可以代入的数字或公式；
- 一个能连续改变状态的日常物件；
- 一个旧做法会得到明确结果的小任务；
- 原书人物正在面对、且材料足以还原的具体时刻。

对象要足够小，使读者不用先学背景就能猜；也要足够稳定，使后面两三次变化仍能回到它。

检验它是否真的能运行：删掉解释后，读者仍能按顺序说出“先是什么—动了哪里—结果怎样”。只剩一个寓意，就只是配图。

## 场景摘要与可运行现场

摘要会把一段时间压成结论：

> 父亲会听机器的声响、检查原因，并根据反馈调整。

它交代了正确事实，却没有留给读者任何未知。可运行现场需要一个确定时刻：某个判断先被采用，一个动作落到对象上，结果与预期不合，人不得不重新看。

不要为了近景虚构零件、天气、对话、表情或心理。若原书材料没有给出这个时刻，说明材料门没有通过，不是文笔还不够好。

## 一个模块怎样成立

一个模块只需要完成一项认识变化：

```text
一个普通问题
→ 稳定对象进入视野
→ 读者凭有限信息猜一次
→ 对象发生一个小动作或条件变化
→ 结果立即回来
→ 这段结果得到名字
→ 同一对象带着新名字再运行一次
```

这不是要求正文显示七个步骤，而是成品必须保住七个认知位置。读者不需要听见写作者的设计，只需要顺着事情自然走过。

命名要贴着结果。若一个概念需要三段解释才与例子相遇，说明动作太大，或者一次塞进了多个关系。把它拆小，而不是增加定义。

## 一本书怎样拥有多个模块

全书通常保留两到四个模块。每个模块只增加一个新关系，但仍由开头的问题牵引。

优先让同一对象继续运行。例如一段手机政策论证可以依次承受：理由与结论的缺口、何种证据能填缺口、替代解释怎样改变政策选择。每一步都回到“现在是否足以支持加重处罚”，而不是分别介绍专家、调查、统计、因果和遗漏信息。

只有对象确实承载不了下一关系时才换。前一个结果要提出换场的理由：最小模型在扩大时失效，人物离开一个关系进入另一个关系，同一制度换到新条件下产生相反结果。

后台的全书问题负责连续性；前台的稳定对象负责低认知负担。

## 不同书型的可运行对象

### 分析与理论

让读者先完成一次判断，再用书中的区分、反例或证据改变判断。一个概念出现后，立即让同一判断再做一遍。

### 方法与实践

让旧做法与新做法各得到一次结果。若作者改变了“什么算有效”，结果标准也要在对象上显出来，而不是附加成建议。

### 技术与科学

建立一个读者能手算、跟踪或预测的最小模型。先让它工作，再用规模、故障或边界迫使模型增加一层。公式保留时，下一句说明数字正在做什么。

### 历史与社会

多个场景可以换，但每次仍回答同一个普通问题。不要为了年代覆盖切换人物；新条件真正改变了结果才换场。

### 文学与哲学

使用材料能支撑的具体人物时刻、关系变化、反复意象或论证困境。人物经历本身可以是结果，不必硬改成方法。没有具体书内时刻时，先补材料。

## 证据怎样进入而不压垮正文

证据只在它改变读者当前判断时进入。

不要一次列出所有证据类型。先问眼前缺的是哪一块：问题是否存在、原因是否成立、办法是否有效、代价是否可接受。随后只放入能回答这一个问题的证据，让它改变同一对象上的选择。

原书案例、作者解释和讲解者自建模型要分清：

- 原书材料决定结论能走多远。
- 作者解释说明他怎样理解材料。
- 自建最小模型只帮助读者运行关系，不能替原书作证。

边界紧跟受限制的判断即可。不要在每个动作后插入来源说明，也不要在末尾集中堆一份免责声明。

## 口头稿先于书面压缩

先按说给一个聪明朋友听的方式读回正文。好的节奏通常是：短问句保留未知，短动作推进对象，短答句确认结果。允许重复同一个普通词，不急着用同义词显得丰富。

每段通常一到三句，只增加一个关系。连续出现三个以上抽象名词时，检查是否跳过了中间动作。警句最后再写；若删掉警句以后机制不见了，说明中间没有讲清。

篇幅通常为 1000–3000 个汉字。复杂书需要更多步骤就增加篇幅，或明确缩小这篇的解释范围；不要靠提高每段概念密度来维持短。

## 标题与返程

标题写读者正在面对的问题、动作或结果。它要让人只看标题也能看到对象继续变化，而不是看到一组漂亮的分析结论。

结尾回到最初的问题，不加入新术语。写清同一个读者现在会先看什么、先问什么、怎样重做那项判断，或为什么愿意保留一个无法消掉的矛盾。

若返程可以放进任何一本书，说明它没有回到这个对象。

## 陌生读者验收

机械检查之后，用成品本身回答：

- 开头的普通问题是什么？
- 稳定对象是什么？它至少发生了哪两次变化？
- 读者第一次为什么会那样猜？
- 哪个结果让原猜法不够用了？
- 概念是否紧贴这个结果出现？
- 不使用术语，能否复述书中改变的判断？

若回答只能引用摘要、术语或结论，回到最早失去对象的段落。不要在结尾补一段“换句话说”。

## 写入与验证

Org 使用 `references/template.md`。正文完成后补 `description`，保留 Denote 文件名与 `#+IDENTIFIER` 一致。

运行：

```sh
bun {skill_dir}/scripts/validate_note.ts /absolute/path/to/note.md \
  --coverage /absolute/path/to/coverage-map.md
```

validator 检查来源边界、覆盖记录、结构与若干可读性退化信号。它不会替代陌生读者复述。
