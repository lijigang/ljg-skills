# ljg-book：让没读过的人，也能读懂这本书

写给没读过原书的人，让他们知道书里具体讲了什么，也明白这些内容为什么会改变我们看待事情的方式。

从一个容易理解的处境、问题或人物经历写起，让读者先明白身在其中的人为什么会这样想、为什么还愿意继续这样做。随着书中的事实、事件和结果，原来确信的事情才逐渐显出遗漏。需要新概念时再介绍，并用眼前的事情说明它有什么用。读者既能理解内容之间的联系，也愿意继续关心眼前的人和事。

贯穿全文的可以是一个问题、一个人物、一段关系，也可以是一个模型。不必始终围绕同一个物件。形式可以变化，读者正在追问的事不能丢。

取舍材料时，同时检查两件事：读者能否顺着文章理解下去，原书的重要内容是否还在。人物、事件、论述和几条主线之间的关系，都不能为了提炼一个好记的道理而被省掉。

## Workflow Routing

| 输入 | 必读 | 输出 |
|---|---|---|
| 书名 | 找到可靠材料后读 `ReadingGuide.md` | 保存 Markdown 笔记 |
| PDF、EPUB、正文、样章、旧笔记 | 先读原文，再读 `ReadingGuide.md` | 保存 Markdown 笔记 |
| 用户明确只要口头解释 | `ReadingGuide.md` | 按同样要求讲清，不写文件 |

写 Markdown 时再读 `references/template.md`。每次任务复制 `references/coverage-map.md`，记录所读材料、内容取舍和检查结果。这份记录简称 coverage，供写作和核对使用，不照搬进正文。

默认保存到 `~/Context/`，文件名为 `{YYYYMMDDTHHMMSS}--拆书-{书名}__book.md`，时间戳由 `date +%Y%m%dT%H%M%S` 生成。

## Gotchas

- **讲得顺，还要讲出这本书本身。** 读者需要知道书中具体写了什么，几条重要线索怎样相连，最后在哪里结束。只有一个适用于许多书的道理，还不算完整拆书。
- **人物刚出现，不要急着让他证明道理。** 「父子骑摩托远行」仍可能只是摘要；补上动作以后立刻解释，也会让人刚进入就退回听讲。先让原有的愿望、判断或疑惑展开，读者理解他为什么如此之后，再看事情怎样改变。
- **不要把所有书写成教程。** 历史可以随条件变化展开，传记可以跟着选择与后果推进，文学与哲学可以逐渐呈现一个无法消除的矛盾。不必都写成「先猜、动手、得答案」。
- **段落之间要有实际联系。** 问题的延续、人物的变化、必要的对照，都可以说明为什么接着讲下一部分。若只靠「另一个例子」「此外」连接，要补清内容之间的关系。换序测试用来发现缺少联系的段落，不要求所有相邻小节都只有一种合理顺序。
- **多个案例谈同一主题，还不够。** 若书中的函数、因果关系、人物选择或贯穿矛盾能解释多处关键变化，就要讲清它怎样起作用。每个案例应当帮助读者多理解一点，避免反复证明同一句话。
- **材料不足时，不补写现场。** 原文没有具体动作、判断或结果，就先找材料；找不到便只解释已有材料支持的部分。「他观察、他调整、现实给出反馈」不能代替真实事件。
- **说明适用范围时，继续围绕眼前的事情。** 自拟例子用「想象一下」「先拿十二根纸条」自然引入，不冒充原书案例。正文说明它能解释什么、还需要什么条件；资料核验和改稿过程留在 coverage。第一人称本身没有问题。
- **读过的材料不必全写进正文。** coverage 保留充分的候选材料，正文选出讲清全书所需的人物、案例和模型。同一段不要塞满证据类型或概念；每个例子都应交代清楚起点、结果和读者因此明白的事。
- **图表要帮助读者看懂具体内容。** 位置、曲线、层级、顺序或精确对应难以说清时，用最小的 ASCII 图或表格。图后马上用一个例子说明怎样读它、能看出什么；不需要图表时不硬加。
- **检查脚本通过，不代表文章好读。** 最后仍要让没读过原书的人只看成品，用自己的话复述。

## 成品要做到三件事

- **让读者知道整本书写了什么。** 能说出书的类型、主要人物或问题、起点与主要变化、结尾，以及几条不可省略的主线为什么写在一起。
- **让读者明白自己的理解怎样改变。** 先有自然的判断或困惑，再看见书中的事实与事件补上了什么，最后能重新理解原来的事情。
- **让读者自己用得上书中的解释。** 若书中有贯穿多处内容的函数、因果机制、过程、人物选择或矛盾，读者能说明它怎样解释至少两处相隔较远的关键转折，换到一个相近情况会怎样，以及哪里不再适用。没有这样的共同解释，就在 coverage 如实记录，不硬凑公式。

这三件事要分别检查。准确概括全书，未必让人理解；讲出一次动人的认识变化，也未必保留了原书。书中若有共同的解释，只列案例仍会把最难的一步归纳留给读者。

开头可以直接进入场景。最迟读完前两个一级标题，读者应当知道书里主要在写谁或什么、事情怎样展开，以及还有哪些必要主线与之相连。

## 让理解逐渐改变

解释出现前，让读者先形成一种自然的理解、期待、选择或疑问，也理解它为什么站得住脚。涉及人的选择时，写清他想保住什么、担心失去什么，以及改变想法要付出什么。技术或分析内容则可以让读者看见一个办法为什么似乎可行、一个判断为什么令人信服，不强加情感故事。

在材料足够的关键处多停留一会儿，让一个念头、一次尝试或一段犹疑发展到原来的解释开始不够用。人物的留恋、体谅、自我说服或不甘，可以使变化被真正体会；不要一开始就用「逃避」「控制欲」「偏见」替人下诊断。事实和后果出现后，解释才回答读者已经感到的问题。

一次讲清当前需要补上的关系、条件或区分，不必每一段都增加知识。一个念头也可以经过几段才说完整。概念可以在一个结果之后出现，也可以等两个例子比较、一次选择付出代价，或一个矛盾反复出现以后再介绍。读者已经看明白的地方，不再追加一段同义的道理；确有必要的解释也不故意拖延。

反例要说明原来的理解在什么条件下不再成立，或两个看似相近的情况为什么结果不同。回看开头时，写清读者的理解发生了什么变化；只有行动或条件实际改变，并产生新后果时，才说结果变了。

场景不必都是故事。分析书可以让读者重做判断，技术书可以让读者跟踪一个最小模型，方法书可以比较两种做法的结果，文学则可以让同一个困境渐渐显出更复杂的含义。每次关键转折之后，读者都应能不用术语说清刚才明白了什么。

## 怎样取舍全书内容

先在 coverage 记录原书的主要内容和几条主线，再选择能贯穿文章的问题、人物或关系。这个选择应当帮助组织原书，不能把原书缩成一个主题的例子。

每次删去内容，都检查理解是否仍然连贯、原书的重要部分是否还在。换人物、年代、对象或场景时，也留意读者刚产生的关切是否得到承接：那件放不下的事、那个尚未兑现的愿望，到了新处境会怎样。必要联系可以由内容自然显出，不必每个段尾都加一句提问来报幕。

完整拆书要求材料覆盖全书，不要求正文展示每一条研究记录。正文没有预设字数、篇幅目标或上限：关键内容需要多少篇幅才能讲清，就写多少。篇幅长时，用标题、留白、必要的重复和具体例子帮助阅读。只有材料不足或用户明确缩小范围时才缩写，不能为了短而把过程压成名词与结论清单。

## 用自然的中文写

- 先写人、物、选择、事件和结果，再说明关系和术语。
- 段落跟着思绪与事情的进展长短变化。可以把一段犹疑连贯写完，也可以让一个发现单独停住；不用固定句数把文章切成同样大小的小段。
- 可以重复同一个普通说法，再逐步补充。不要为了避免重复，不断更换读者刚熟悉的词。
- 问句要保留此时确实不明白的事，不必紧接标准答案。避免反复使用「案例—解释—边界—提问」的节拍；需要的事实与边界在它们真正影响理解时说明。
- 「这就是……」「也就是说……」只在确实需要解释或命名时使用，不作为固定收尾。
- 可以用「我」呈现判断、迟疑和重做，也可以用「你」邀请读者进入明确的假想处境。人称一旦选定，让读者在其中待得住，不频繁切回场外评论。
- 沉浸依靠准确的处境、具体的关切和自然的节奏。人物的动作、对话和心理必须有材料依据；分清他当时经历了什么、后来怎样回忆、只是希望发生什么。不为感人添加天气、表情、内心独白或虚构的顿悟。
- 想写一句让人记住的话，先确认前面的事情已经讲清。漂亮句子不能代替解释。
- 抽象名词堆在一起时，重新写清谁做了什么、发生了什么、读者因此明白了什么。若替换近义词仍显生硬，就重写整句。
- 标题写读者正在面对的问题、事件、变化或结果。除末节外，不套固定栏目名。
- 朗读时检查是否突然插入了查资料、核验或改稿的过程；这些移回 coverage。原书本身涉及写作者或旧稿时，照常讲清书中内容。

例如，说明一个模型的适用范围，可以写：「纸条能让你看见连接方式怎样改变受力，却算不出钢梁能承受多少吨。真正计算时，还要考虑截面、缺陷和载荷。」

## 末节：读完后留下什么

结尾回应开头的问题以后，以最后一个一级标题「读完后留下什么」收束。下面只写一个自然段，通常一到四句，回答：读完整本书，作者最想让读者明白的是什么？

可以从全书的安排、关键发现、模型、反复出现的矛盾、意象或书名中寻找答案。这些只是思考的入口，不列成栏目，也不要求逐项出现。

用直白的话说明作者在纠正哪种误解、讲清什么关系，或保留哪个无法消除的矛盾。书名本身包含这层意思时，自然解释为什么叫这个名字；书名只是题材标签时，不强行解释。

这段话要有正文中至少两处相隔较远的关键转折作为依据，不能只重述最后一节。它不列清单、不概括章节，也不加入新术语、新事实或行动建议。删掉书名和专名后，若只剩「要系统思考」「类比很重要」「人应该成长」之类适用于许多书的话，就重新写得具体些。

## 只看成品，能否复述

评估者只读最终正文，不看 coverage、原书、写作者分析或预期答案。先回答四个关于整本书的问题：

1. 这是什么样的一本书？不能只回答「成长、自由、未知、选择」这类主题。
2. 书里具体跟着谁、什么对象或什么问题展开？起点、主要变化与终点是什么？
3. 哪些主线不可省？它们为什么写在同一本书里？
4. 结尾发生了什么或得出了什么？哪些得到解释，哪些仍然未知或没有解决？

任一题只能给出适用于许多书的抽象回答，就回到遗漏人物、事件、论述或必要主线的地方重写。

四问通过后，再回答九个关于理解过程的问题：

1. 开头让我进入了什么具体处境、困惑或人物经历？
2. 我一开始最自然会怎样理解？这个想法为什么有吸引力，改变它会放下什么？
3. 哪个事实、事件或结果让这种理解需要补充或改变？
4. 新加入的关系说明了什么？它怎样改变我对原来事情的理解？
5. 每次换场与前面有什么具体联系？除了内容的联系，刚刚产生的关切是否还在？
6. 试着交换相邻小节：哪些前提、对照或认识变化会受影响？若顺序可以调整，它们共同说明什么，为什么采用现在的安排？
7. 不用书中术语，我能否说清这本书改变了什么？
8. 结尾回应开头以后，我现在会怎样重新看那件事？
9. 是否有交代查资料、核验或改稿过程的句子打断了理解？

前八题若只能复述结论，说不清具体事情和内容之间的联系，就补足缺失的事实与解释。若能回答「他哪里想错了」，却说不出「他为什么愿意这样想」，就回到过早下结论的地方，补清原有判断的理由；若材料没有提供理由，不替人物编造。第六题检查安排是否有理由，不单凭可换序判定失败。第九题若发现制作过程插入正文，就移回 coverage；第一人称或书中人物的写作活动本身不算问题。

这两组问题不能互相代替。最后再单独按「末节：读完后留下什么」核对收束段。

## Examples

**例一：分析书让读者重做判断**

不要这样写：

> 四句话构成一段规范性论证。前三句说明风险存在，第四句转向政策选择，其中隐含效果假设与代价假设。

可以让读者亲手检查一次：

> 群里转来四句话。前三句都在说开车看手机有多危险，最后一句说：所以处罚应该更重。你的手已经准备点赞了。
>
> 先把最后一句遮住。前三句能证明什么？只能证明问题严重。现在把最后一句放回来：更重的处罚一定更有效吗？这份材料没有说。刚才那一下点头，把「问题很严重」当成了「这个办法很有效」。理由和结论之间缺的，正是这一步。
>
> 再换一条证据进来：如果相近地区提高处罚后事故没有下降，你还会点头吗？要支持同一句结论，现在需要更具体的证据。批判性提问让你知道，推理中的哪一步还没有被证明。

读者先自然地点头，再发现判断缺了什么，随后知道还需要哪一种证据。这里不用一次讲完整套证据分类。

**例二：几条主线交织的书**

一本书交替写某种动物的迁徙史与一个家庭的回忆。开头可以进入一次共同观察或捕捉，随后讲清动物走过怎样的生命历程、家庭关系怎样变化，以及两条线为什么在「从哪里来、怎样回去」这个问题上相遇。动物和家人的真实经历都要保留，不能很快缩成「归属感」的两个例子。

## Completion

- coverage 如实记录材料等级、实际来源、能支持的范围，以及材料是否足以说明读者的理解怎样改变。材料不足时补原文或缩小解释范围，不虚构现场。
- 完整拆书记录四类全书证据、至少 5 项候选材料、内容取舍与反证检查；复杂书按需要增加，不设上限。细则见 `ReadingGuide.md`。
- 正文包含 coverage 列出的全部原书具体短语：完整拆书至少 3 个，初拆或假设版至少 1 个，都有真实材料支持。
- 书中若有共同的解释，能说明它怎样用于两处相隔较远的关键转折及相近情况，哪里不再适用。正式模型的坐标、单位和结果方向保持一致。
- 正文所选人物、案例或模型来自 coverage 的候选材料；能复述起点、原有判断的理由、结果与理解的变化。读者有机会经历变化，不是刚看见例子就被带回听结论。
- coverage 声明需要图表时，正文有一个不超过 80 显示列的最小图块，图后立即用已记录的例子说明怎样读图；不需要时不硬加。
- 四个整书问题与九个理解问题都能用日常话回答；末节符合「末节：读完后留下什么」的要求。
- 文件头、`description` 与 Denote identifier 完整，identifier 与文件名一致。
- validator 没有 error；逐条读回 warning，不把脚本通过当作易读证明。
- 用真实 Emacs 读回成品：`denote-retrieve-filename-identifier` 与文件名一致，`denote-file-has-denoted-filename-p` 为真，文件出现在 `denote-directory-files` 与 consult-notes 中。如实报告检查结果；验证器不可用时明确延期，不把未执行写成通过。

写入 Markdown 后运行：

```sh
bun {skill_dir}/scripts/validate_note.ts /absolute/path/to/note.md \
  --coverage /absolute/path/to/coverage-map.md
```
