# ljg-book：让读者亲手走进一本书

通俗不是把结论换成白话，而是让读者在术语出现以前，已经亲眼看见一点答案。

成品从一个普通人会问的问题开始。给读者一个可以在脑中运行的最小对象：一次选择、一组数字、一件工具、一项操作、一个人物正在面对的时刻。让他先猜一次，再让对象发生一个很小的变化。结果立即回来，概念紧跟结果得到名字。后面的解释继续使用同一个对象，直到这本书真正改变的判断、做法或观看方式显出来。

全书研究负责保证没有讲偏；前台只保留读者此刻需要的一步。完整拆书不等于把全书压进正文，而是后台读全，前台做出准确取舍。

## Workflow Routing

| 输入 | 必读 | 输出 |
|---|---|---|
| 书名 | 找到可靠材料后读 `ReadingGuide.md` | 保存 Markdown 笔记 |
| PDF、EPUB、正文、样章、旧笔记 | 先读原文，再读 `ReadingGuide.md` | 保存 Markdown 笔记 |
| 用户明确只要口头解释 | `ReadingGuide.md` | 按同一可运行方式口头讲，不写文件 |

写 Org 时再读 `references/template.md`。每次任务复制 `references/coverage-map.md` 建立后台记录。默认保存到 `~/Context/`，文件名为 `{YYYYMMDDTHHMMSS}--拆书-{书名}__book.md`，时间戳由 `date +%Y%m%dT%H%M%S` 生成。

## Gotchas

- **具体名词不等于事情发生。** “父子骑摩托远行”仍可能只是摘要。读者要看见一个时刻怎样按先后展开：先知道什么、先怎么猜、做了什么、结果怎样回来。
- **一个稳定对象比一条漂亮张力更能减轻负担。** 筷子、火苗、三参数模型之所以好懂，是因为解释一直没有换扶手。概念一多就换对象，读者会反复重建背景。
- **整本书不能靠概念压缩来显得完整。** 一段塞进专家、调查、统计、替代原因和边界，只会得到正确而费力的摘要。后台保留覆盖，正文每次只增加一个关系。
- **动作之后要立刻得到结果和名字。** 若场景之后连续总结几段，例子就退化成插图。读者刚看见什么，就在相邻句子里知道它叫什么；命名后马上回到同一对象。
- **讲述者不能永远站在终点。** 第一人称不是必需，但读者必须有机会先猜、先误解或先看到一个不够用的办法，而不是只接收已经整理好的答案。
- **薄材料可能无法支撑现场。** 没有具体动作、判断或结果时，先补材料；补不到就缩成局部理解。不要用泛化的“他观察、他调整、现实反馈”伪装成书内事件。
- **边界不能把讲述者带进镜头。** 自建对象可以帮助读者运行关系，但它的身份、依据和材料状态只写进 coverage。正文用“想象一下”“先拿十二根纸条”“试着把它折起来”自然进入，再写这个对象已经回答了什么、走到哪一步还需要真实条件。不要交代谁构造了模型、根据哪份旧稿、本轮核到哪里，也不要写“不能替……作证”。这样既不冒充原书，也不把故事改成免责声明。
- **机械检查只能暴露退化，不能证明易读。** validator 通过以后，仍要做陌生读者复述门。

## 成品合同：一个能运行的读者问题

一篇成品应当让读者得到以下体验：

- 开头是他能马上回答、选择或预测的日常问题，不是“这本书讨论什么”。
- 一个对象、人物时刻或最小模型在连续几段中保持不变。
- 解释出现前，读者已经凭有限信息猜过一次；不要预先暗示正确答案。
- 每次只发生一个小动作或条件变化，结果在眼前出现。
- 抽象名字紧挨着它所命名的结果；名字出现后，同一对象立即再运行一次。
- 反例不是口头罗列，而是旧办法在对象上真正失效，或一个相邻情况得到不同结果。
- 每个模块结束时，读者能不用术语说回“发生了什么、为什么原来的猜法不够”。
- 结尾回到开头的问题，不再加入新概念；读者现在会看见、询问或行动得不一样。

场景不必都是故事。分析书可以让读者重做一次选择；技术书可以运行一个最小模型；方法书可以让旧做法与新做法各得到一次结果；文学和哲学要进入原书能支持的具体人物时刻。共同标准只有一个：读者能跟着它运行，而不是只能听人概括。

## 整书与模块

后台先找到全书反复处理的一个问题，用它筛掉无关材料。正文通常只保留两到四个可运行模块，每个模块承担一个新关系。前一个结果能自然提出下一个问题时才换模块；同一对象还能继续承载，就不要换。

“完整拆书”说明证据覆盖整本书，不要求正文展示所有候选部件。若理解一项判断需要五步，就写足五步；若篇幅变长，增加留白或缩小范围，不把五步压成一串抽象名词。通常 1000–3000 个汉字，以读者能顺畅走完为准。

## 写作声音

- 先写对象、动作和结果，再写关系和术语。
- 一小段只让读者多理解一件事；通常一到三句，长句拆开。
- 允许有意重复同一个普通说法，再逐步增加变化。重复能让读者保住扶手。
- 用问句保留未知，用短答确认刚发生的结果。不要用问句假装互动、下一句却塞入整套答案。
- “这就是……”“也就是说……”只在前一句已经出现可见结果时使用。
- 可以让“我”或人物犯错、迟疑、重做；不要站在高处诊断“人们总是怎样”。
- 先让正文负责听懂，最后才允许一句警句负责记住。警句不能替代中间过程。
- 边界用对象自身收住。例如：“纸条看得见连接怎样改变受力，却算不出钢梁能承受多少吨；真正计算还要加入截面、缺陷和载荷。”不要改写成“本轮未核”“不是书中案例”或“不能替工程结论作证”。
- 朗读时，若一句话像在向审稿人交代资料、核验过程或责任，把它移回 coverage；正文只留下人、物、动作、结果和接下来必须加入的条件。
- 标题写读者正在面对的问题、动作或结果，不写后台步骤。

## 证据与材料门

完整材料仍需在后台覆盖：作者为什么处理这个问题、观察对象怎样建立、机制怎样运行、结论停在哪里，并保留 5–12 个候选部件与删除测试。

coverage 中先回答“材料能否支撑具体运行”。若答案为否，不能把“场景化”当成必须完成的修辞任务：继续找原文，或把输出明确缩成证据允许的局部理解。文学、哲学和叙事作品尤其如此；没有书内时刻，就没有资格替人物补动作、感受或反馈。

## 陌生读者复述门

交付前，暂时忘掉写作者的分析，让一个只读成品的人回答：

1. 开头让我面对了什么具体问题？
2. 我第一次会怎么猜，结果为什么顶住了它？
3. 哪个动作或结果紧接着得到了什么名字？
4. 后面是否仍在运行同一个对象，还是变成了概念清单？
5. 不使用书中术语，我能否说回这本书改变了什么？
6. 哪一句让我突然看见讲解者、旧稿、核验过程或免责声明？

前五题任一题只能复述抽象结论，说明讲解仍在场外；第六题若能指出一句，说明后台泄漏。回到最早失去对象或跳出现场的地方重写，不靠增加定义或免责句补救。

## Quick Reference

- 读全书是为了取舍，不是为了把全部内容压进正文。
- 先给普通问题和稳定对象，让读者猜一次。
- 一次只动一下；结果出现，立即命名，再用同一对象重跑。
- 材料不够就停，不用泛化场景冒充原书现场。
- 证据身份进 coverage；正文用对象的能力边界自然收住，不写免责句。
- validator 负责结构；陌生读者复述负责易读。

## Example

不要这样写：

> 四句话构成一段规范性论证。前三句说明风险存在，第四句转向政策选择，其中隐含效果假设与代价假设。

可以让读者亲手走一次：

> 群里转来四句话。前三句都在说开车看手机有多危险，最后一句说：所以处罚应该更重。你的手已经准备点赞了。
>
> 先把最后一句遮住。前三句能证明什么？只能证明问题严重。现在把最后一句放回来：更重的处罚一定更有效吗？这份材料没有说。刚才那一下点头，把“问题很严重”当成了“这个办法很有效”。理由和结论之间缺的，正是这一步。
>
> 再换一条证据进来：如果相近地区提高处罚后事故没有下降，你还会点头吗？同一句结论，现在开始等一种更具体的证据。批判性提问不是先反对，而是知道哪一步还没有被证明。

这里没有把整套证据分类一次讲完。它先让同一个判断运行、受阻、得名，再为后面的调查、统计和替代解释留下入口。

## Completion

- 后台 coverage 记录真实材料、支持边界与“能否支撑具体运行”。
- 完整拆书仍有四类全书证据、5–12 个候选部件和反证。
- 成品保留稳定对象；第一猜、微动作、可见结果、即时命名和重跑能够逐句指出。
- 没有用场景摘要、概念清单或漂亮警句替代运行过程。
- 薄材料没有被虚构成完整现场。
- 正文没有讲解者、旧稿、本轮核验、未核或“不能替……作证”等后台语言；必要边界仍由对象能回答什么、还需什么条件说清。
- 文件、frontmatter、`description` 与 Denote identifier 完整。
- validator 无 error；warning 已读回，不把机械通过当作易读证明。
- 陌生读者复述六问可以用日常话回答，且不会被资料管理或免责声明拉出现场。

写入 Markdown 后运行：

```sh
bun {skill_dir}/scripts/validate_note.ts /absolute/path/to/note.md \
  --coverage /absolute/path/to/coverage-map.md
```
