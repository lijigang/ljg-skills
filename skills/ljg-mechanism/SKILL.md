# ljg-mechanism · 机制研究

从眼前的现象中找出真正起作用的关系。生成解释后，让它与竞争解释一起接受现实检验；根据证据修正对象、关系或成立条件，给出当前最扎实的机制判断。

「solid」指关键关系有可检查的依据、能够区分竞争解释、能推出新观察，并留下修改自己的入口。完整、流畅或引用很多，均不足以达到这个标准；公开证据不足时，交付领先猜想和具体缺口。

## Workflow Routing

| 请求 | 执行 |
|---|---|
| 提供现象，希望解释其生成过程并验证 | 阅读 [Workflows/DiscoverMechanism.md](Workflows/DiscoverMechanism.md) |
| 希望示范、学习或「走一遍」 | 使用同一研究框架，在成品中展开四个环节与判断变化 |
| 补充新事实、反例或改变范围 | 回到受影响的观察或因果关系，更新判断，不从头重复无关部分 |

## 研究约定

- 原始现象也需要核对。保留有价值的观察，明确对象、指标、比较基准和时段；「大家」「越来越」「没有效果」等概括不能直接当全称事实。
- 机制说清「谁或什么，在什么条件下，通过哪些中间变化，生成什么结果」。「供求」「激励」「文化」「系统」等名称须展开到可观察的过程。
- 保留能争夺同一解释对象的竞争解释，写出它们会产生的不同观察。方向不同、时间不同、影响的人不同，也可以形成区别性预测。
- 默认使用当前可用的联网搜索与正文获取能力，检验现象和机制。来源支持的范围，与自己的推断、教学设例和未知分开。
- 新材料可以推翻、重写或收窄机制。声明后的反例不能靠不断追加例外消解；需要说明原预测为何失败、新关系会推出什么不同结果。

## 成品

默认中文，直接在对话中交付。先给机制判断与证据强度，再以具体对象讲清过程，展示最能改变判断的竞争解释、证据与边界。四步是研究框架，不要求把全部检索过程或思考过程打印出来。

涉及关键因果时，把来源链接放在对应判断旁边；说明来源实际支持的是现象、机制环节还是因果关系。正文应让读者看见：当前相信什么、为什么、什么观察会使它改口，以及换个现场时必须保留哪些条件。

用户要求完整示范时，按「看反常 / 追过程 / 分解释 / 带条件迁移」展开。比较确有帮助时用短表，承重关系难以看清时用简图；不给每个简单问题硬加图、公式或固定数量的假说。

研究默认只读，不自动创建笔记、报告文件、日志、规则或记忆。用户另行要求保存时，遵循指定位置与格式。联网不可用或用户要求离线时，说明只完成了推演，不能声称已联网验证。

## Gotchas

- 反常既包括「预期条件缺失，结果却出现」，也包括「条件已出现，预期结果没有出现」。普通现象也可以通过重新追问其生成过程成为研究对象。
- 产能、产出、合格交付、成交、收入、利润与单位时间回报是不同指标；平均变化、个体变化和群体构成变化也要分开。
- 一个来源证明现象发生，不自动证明候选机制成立。把同一论文的多次转述计作多个独立证据，会夸大支持。
- 没找到反例不等于通过验证；未显著不等于无效；缺少区分证据时可以同时保留多条解释。
- 跨域类比可生成猜想，不能代替当前领域的证据。迁移时既要保留关系，也要检查关键条件与失配处。
- 一个反例是否改变总体判断，取决于原来的命题口径。不能用一个赢家否定平均停滞，也不能用平均停滞否定个体获益。

## Examples

- `/ljg-mechanism AI 让创作容易了，为什么收入没有同步增长？`：拆开产能、交付、成交、价格与净收益，比较需求瓶颈、竞争替代和中间环节提速等候选解释，再检索能区分它们的材料；不预设所有领域都由同一机制主导。
- `没人统一指挥，为什么群里的问题仍能找到回答者？走一遍这个框架。`：对照成员自行认领与少数人集中撮合，找出关键参与者缺席时的不同预测；缺少该群的过程证据时，保留为待检验解释。
- `网上都说某项技术没有实际效果，帮我找机制并验证。`：先核对「效果」的指标、时期和适用群体；原始概括不成立时，改写研究问题，再解释哪些环节改善、哪些环节仍然卡住。
