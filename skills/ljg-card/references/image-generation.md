# 共享图像生成协议

这份协议决定三种图像型 mode 怎样从文本得到生成位图。`-f` 默认不生成新图，只在原稿自带图片时读取来源保真条款；其他 mode 文件只追加自己的视觉语法，不得复制或改写这里的共同合同。

## 一、先判定资产身份

每个视觉资产先归入一类：

| 类型 | 含义 | 处理 |
|---|---|---|
| `generated` | 为这张卡新生成的概念场景或物件 | 进入本协议 |
| `source` | 原文照片、图表、截图或证据 | 本地缓存，保真引用，标来源 |
| `brand` | 既有 logo 或头像 | 原样保留，不充当内容图 |
| `structural` | 文字、数字、箭头、轴线、标签、分格 | 用 HTML/CSS 实现 |

不得把 `source` 重生成后说成原图，也不得把 `structural` 交给图片模型排版。

## 二、建立视觉母题表

写提示词前先完成表格；一行对应一个候选资产：

| asset_id | 源判断 | 核心冲突 | 视觉动词 | 承载物 | 独有隐喻 | 图像角色 | 比例 | 文字安全区 | 色彩/媒介 | alt |
|---|---|---|---|---|---|---|---|---|---|---|
| `g01` | 一句可核对的判断 | 两股力量怎样相撞 | 切开/拉扯/翻转/聚拢 | 具体人物或物件 | 本图不与别图重复的构思 | hero/scene/detail/vignette | 4:3 等 | left/right/top/none | mode 规定 | 具体动作及意义 |

母题表必须满足：

1. 「视觉动词」能被拍到或画到；避免「体现、象征、赋能」。
2. 「承载物」是具体的人、手、门、绳、容器、地形或机器，不是抽象概念名。
3. 「独有隐喻」在同一成品中只出现一次。
4. 安全区由后续文字布局决定；没有文字覆盖就写 `none`。
5. 资产数量由叙事需要决定，不能为填空而新增。

## 三、建立系列圣经

有两幅以上生成图时，先锁定系列圣经：

- 媒介：线描、木刻、新闻插画、拼贴、摄影等，只选一种主媒介。
- 线条与材质：粗细、颗粒、纸面、网点或光线逻辑。
- 角色与物件：年龄、发型、服装、比例、关键道具、左右手等连续特征。
- 镜头：视平线、焦段感、景别范围、是否允许俯拍或极端透视。
- 色彩：背景色、墨色和最多两种强调色。
- 构图：系列共同的留白方向与主体占比。

同系列可以换隐喻与动作，不能每张换一套世界观。

## 四、提示词骨架

按以下顺序写正向提示词：

```text
[输出类型与媒介]。
Scene: [可见场景、主体、关键动作、冲突结果]。
Composition: [比例、主体位置、景别、视觉焦点、文字安全区]。
Series style: [系列圣经中的线条、材质、色彩、角色连续性]。
Semantic role: [它对应哪条源判断，以及读者应先看见什么]。
Background: [transparent 或 mode 指定的纯色平底]。
No readable text inside the image.
```

提示词先写具体场景，再写风格；不要用一串风格形容词代替画面。若要求透明背景但工具不稳定，使用与模板完全一致的纯色平底，并在资产记录中注明。

## 五、统一负向约束

每次生成都附加：

```text
no readable text, no letters, no numbers, no logo, no watermark,
no captions, no labels, no speech bubbles, no interface panels,
no generic AI brain, no robot mascot, no decorative stock illustration,
no gradient, no glow, no glossy 3D, no heavy drop shadow,
no unintended extra limbs or objects, no cropped key subject
```

mode 文件可以追加专属负向约束，但不能删除这些共同项。

## 六、先样图，后批量

1. 从母题表选最能代表系列的 `g01`。
2. 只生成这一张，检查语义、构图、安全区、角色、背景、无字和色彩。
3. 只改一个失败变量后重生；不要同时换隐喻、镜头和风格。
4. 样图通过后，锁定系列圣经，再生成其他资产。
5. 每个失败资产最多两次定向重生；仍失败则停止该 mode 的交付。

## 七、调用图像生成工具

- 使用当前运行时可用的 image generation 工具实际生成图片；禁止用 HTML/CSS、图标或远程图库假装完成了主视觉。
- 新图从母题表的一行构造一次完整 prompt。不要把整篇文章原样扔给图片模型，让它自行猜画面。
- 工具支持参考图时，只把已经通过校准的系列样图用于角色/媒介连续性；不能把原文证据图改造后冒充原图。
- 每次调用只改变母题表中明确的失败变量，并把结果对应回唯一 `asset_id`。
- 工具返回临时资产后，立即保存到当前卡片的本地工作目录；未落盘的返回值不算完成。

## 八、落盘与资产记录

生成图必须先保存为本地 `.png` 或 `.jpg`，再进入 HTML。稳定命名：

```text
{name}-{mode}-{asset_id}-{role}.png
```

在工作记录中保留：资产 ID、角色、提示词摘要、尺寸、文件路径、SHA-256、来源类型。两种不同角色不得复用同一哈希。禁止远程生成图 URL、随机图库和临时占位图进入成品。

写 HTML 前逐一确认：

- 文件存在且非空；
- 像素尺寸与母题表比例一致；
- 主体没有被裁掉，安全区方向正确；
- 没有可读或伪造文字、Logo、水印；
- `alt` 非空，描述可见动作与语义，不写风格赞美。

## 九、HTML 集成

所有图片使用本地路径：

```html
<figure class="generated-art generated-art--ROLE" data-asset-id="g01">
  <img src="/absolute/local/path.png" alt="一只手把两股相反方向的绳索拉回同一支点">
  <figcaption>由 HTML 写准确说明；图片本身不排字。</figcaption>
</figure>
```

- 主图可用 `object-fit: cover`，但关键主体必须落在安全区内；概念物件优先 `contain`。
- 模板顶层槽无图时使用 `data-state="empty"` 并替换 `src` 与 `alt` 占位符为空；CSS 必须隐藏整个 `figure`，不显示破图图标。
- 标题、来源、数值、公式、坐标、箭头、批注和对话泡统一由 HTML/CSS 叠加。

## 十、验收与失败合同

截图前等待 `document.fonts.ready`，再确认每个 `img` 都满足 `complete && naturalWidth > 0`。任一图片失败就不截图。

最终检查：

1. 资产数量与当前 mode 的预算一致。
2. 每图能回指母题表中的一条源判断。
3. 同系列角色、物件、媒介和色彩连续；隐喻与构图不重复。
4. OCR 或人工检查没有可读/伪文字。
5. HTML 中无未替换占位符，所有 `alt` 有意义。
6. PNG 的修改时间晚于 HTML 与所有生成图资产。
7. 整图与分段像素检查均通过后才交付。
