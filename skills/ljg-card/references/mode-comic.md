# 模具：漫画（-c）

把内容铸成黑白漫画分镜。生成位图负责让角色、场景、动作与结果可见；HTML/CSS 负责把概念名、对白、旁白、音效字、证据分寸与来源写准确。

## 1. 先把解释变成认知因果拍点

Read `references/image-generation.md` 与 `assets/comic_template.html`。确认标题、作者、来源与事实边界；输入若是已验收 Org，先锁定路径与 SHA-256，制卡完成后确认源文件未变。

先找一个能承载核心机制的最小可运行案例。它必须让读者看见输入、动作和结果；删掉关键反馈、时序或约束会改变结论时，那一项必须保留。优先让同一角色、道具与空间贯穿全篇，因为漫画的理解力来自前后可比较，不来自每格换一个漂亮隐喻。

分镜按下面的因果引擎生长：

```text
最小案例 -> 零号模型运行 -> 一个可观察缺口
         -> 一个概念补位 -> 同案重跑 -> 下一个缺口
         -> 完整模型重跑 -> 迁移或失效边界
```

每一步都要改变读者此刻能解释的东西：

1. **最小案例**：建立具体处境，让目标和约束进入画面。
2. **零号模型**：让读者最自然的旧解释或旧做法真的行动一次。
3. **可观察缺口**：用失败结果、错误预测、混淆或代价证明当前模型不够。
4. **单概念补位**：只引入解决当前缺口的一件东西，让它成为动作、选择或结构变化。
5. **同案重跑**：回到相同任务，画出加入它以后最先改变的结果。
6. **继续或停下**：仍有承重缺口才进入下一轮；当前模型已经够用就停止加概念。
7. **整体回收**：从最初输入重新跑完整机制，让沿途零件接回同一台机器。
8. **边界拍点**：必要时改变一个条件，画出模型迁移成功或首先失效之处。

格数不设固定范围。短内容可以合并不承重的铺垫，长文、论文或整本书则从完整因果主线选择拍点；删除某格后若读者仍能完成同样的认知跳跃，这格就是装饰，应合并或删除。不能继承旧五格、六格或任意模板格数，再把内容硬塞进去。

每个分格只承担一个可见动作或一个可比较结果。概念先以动作显示必要性，术语在下一处 HTML 旁白、对白或标题中命名；不要第一格就端出完整答案，再用后续画面复述它。

强耦合、并发或概率涌现的机制不能伪造成单线升级。使用并排分格、同一时刻的双视角或状态对照，让几股力同时显形；读者仍应看见「少了其中一股会先改变什么」。

## 2. 漫画系列圣经

批量生成前锁定四类连续性：

1. **角色设定**：年龄、脸型、发型、服装、身高差、关键道具、左右手。
2. **线条与网点**：线宽、墨块比例、网点颗粒、背景简繁。
3. **镜头语法**：主景别、视平线、允许的透视强度、反应镜头规则。
4. **黑白关系**：纸白、墨黑、灰阶数量与高对比出现的时机。

不要指定模仿真实漫画家。按内容选择描述性风格族：

| 风格族 | 适合内容 | 视觉特征 |
|---|---|---|
| 精密机械线稿 | 技术、系统、装置 | 清楚结构、细线、克制网点 |
| 墨韵留白 | 哲学、内省、历史 | 大留白、毛笔感、安静景别 |
| 高对比暗黑 | 风险、权力、困境 | 大墨块、硬光、压迫构图 |
| 粗线动势 | 冲突、行动、速度 | 粗线、夸张透视、强运动方向 |
| 静谧电影线描 | 人物、关系、日常 | 中远景、环境叙事、低密度网点 |

## 3. 分格因果表

生成前先写分格因果表。所有漫画主画面都必须是本地生成位图；重要拍点可加 detail/reaction，但它必须帮助读者看见当前动作或结果，不能只调节气氛。

| panel_id | cognitive role | reader knows before | visible action | observable result | gap / new relation | continuity anchors | ratio | safe zone |
|---|---|---|---|---|---|---|---|---|
| `p01` | 最小案例 | 只知道目标 | 角色按直觉开始任务 | 旧模型开始运行 | 尚未命名 | 服装、道具、空间 | 16:9 | top |
| `p02` | 可观察缺口 | 相信旧模型够用 | 动作撞上约束 | 结果偏离预期 | 当前缺口 | 同角色、同任务 | 4:3 | left |
| `p03` | 概念补位 | 已感到缺东西 | 角色加入一个新区分 | 第一处结果改变 | 新关系，术语后置 | 同道具、同机位 | 1:1 | right |
| `p04` | 同案重跑 | 理解新关系 | 相同任务重新执行 | 前后差异可比较 | 是否仍有缺口 | 同角色、同空间 | 16:9 | top |

表中每格必须通过三问：

1. 去掉它，读者是否会失去一次必要的认知变化？
2. 它与前后格是否共享足够的角色、动作或结果，可以直接比较？
3. 图片中的动作能否独立成立，而不是全靠旁白声称「这里发生了变化」？

任何一问为否，先重写拍点，不进入图片生成。

## 4. 分格图像生成

提示词追加：

```text
black-and-white manga panel art, clean paper background, coherent recurring character,
single readable action, visible cause-and-effect result, intentional camera angle,
controlled screentone and ink mass
```

专属负向约束：图片内不要对白泡、格线、旁白框、音效字、页码和彩色元素；不要照片感、光滑 3D 或多余角色。关键主体需完整，方便 CSS 裁切。

先生成最能校准角色、空间和核心动作的代表格，不必机械选择 `p01`。样图通过后再生成余格；每次都把角色锚点、当前动作、可观察结果和安全区写回提示词，不能只写「same character」。

逐格检查：读者只看位图，应能指出谁做了什么、什么结果变了；但概念名、结论、数字和证据等级仍留给 HTML。生成图若把术语、界面标签或对白直接画进图片，定向重生。

## 5. 来源分流

- 原文照片、截图或图表属于 `source`，保真放入独立证据格并标来源。
- 新漫画画面属于 `generated`，不能写成「原图」或暗示出自原作者。
- 品牌 logo 只在 footer。
- 同一格不得把来源图与生成图无说明地拼成伪证据。
- 案例让机制可见，不提供普遍性证明；事实主张与论文结论只推进到相邻来源证据允许的位置。

## 6. HTML/CSS 分工

图片写法：

```html
<figure class="generated-art generated-art--panel panel-wide" data-panel-id="p01">
  <img src="/absolute/path.png" alt="主人公按原办法推动机器，齿轮在第二个接口处卡住">
</figure>
```

用 HTML/CSS 叠加：

- `.panel` 格线与不等宽网格
- `.bubble` 对白泡与尾巴
- `.narration` 旁白框
- `.sfx` 音效字
- `.caption` 来源或时间

旁白和对白只承担三种工作：点明读者刚看见的缺口、在必要性出现后给概念命名、校准证据与边界。若文字必须替画面解释「谁做了什么、结果如何变化」，说明动作格还没有设计完成。

图片 `object-fit` 可以是 `cover`，但眼睛、手、关键道具和冲突点必须留在安全区。不同宽高比逐格决定 `cover` 或 `contain`；不能把一个裁切规则无检查地套给所有分格。

顶部图片槽使用 `.generated-visual--comic`，可作为封面 hero；不用时设为空。将版式 CSS 写入 `{{CUSTOM_CSS}}`，分格写入 `{{CONTENT_HTML}}`，替换 `{{LOGO}}`、`{{SOURCE_LINE}}` 与图片槽。写入 `/tmp/ljg_cast_comic_{name}.html`。

## 8. 自检

- [ ] 格数来自认知因果拍点，没有继承固定格数或为版面凑格
- [ ] 最小案例、零号模型、可观察缺口、单概念补位、同案重跑与整体回收均可定位
- [ ] 每个新概念都由前一格的缺口拉入，术语晚于必要性出现
- [ ] 每个分格只有一个可见动作或一个可比较结果，顺序能脱离解释读懂
- [ ] 强耦合机制若存在，使用并排关系而非虚假线性顺序
- [ ] 长内容覆盖完整因果主线；删除测试没有发现装饰格或缺失承重拍点
- [ ] 所有漫画主画面来自生成位图；无空格、占位格或重复哈希
- [ ] 角色设定、线条、镜头、空间、道具和网点风格在全篇连续
- [ ] 格线、对白、旁白、术语、音效与来源全部由 HTML/CSS 承担
- [ ] 图中无可读文字、泡框、格线、Logo、水印或彩色污染
- [ ] 来源原图与生成图标注清楚，主张没有越过来源证据
- [ ] 每个生成资产在进入 HTML 前都做过原尺寸视觉检查
- [ ] 所有分格经过 DOM class-sweep；关键脸、手、道具和动作没有被裁掉
- [ ] PNG 宽 1080，整图与覆盖全部高度的重叠分段检查通过
