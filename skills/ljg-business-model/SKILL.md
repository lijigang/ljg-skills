# ljg-business-model

把用户的信息变成一张能看清「为谁创造什么价值、如何交付、如何收支」的商业模式画布。主产物为中文横版 PNG；同时保留 HTML 和结构化 JSON，便于修改、追溯与重绘。

## Workflow Routing

| 输入 | 处理与交付 |
|---|---|
| 项目介绍、访谈、文档、零散描述 | 依据下方合同整理，运行 `Tools/Render.ts`，验证后交付画布 |
| 现有画布与补充材料 | 以新材料更新指定模型；保留未受影响的信息，重新生成 |
| 多个独立业务／商业模式 | 每个模式一张画布；同一平台的多边客户留在同张图中并用 C1、C2 关联 |

## 内容合同

- 开始前确认对象与范围。只给公司名且没有任何业务资料时，询问业务描述或经用户授权补充研究；信息够画初稿就直接画，缺项写「待补充」。多个可能对象会改变画布时，先问一个聚焦的问题。
- 读取 [CanvasGuide.md](CanvasGuide.md) 校准九模块的定义、关系与经典布局。用用户材料为主体，不自动用行业常识补成事实。
- 每个要点标记 `given`（材料提供）、`inferred`（推测）或 `unknown`（待补充）。「材料提供」不等于外部验证。`given` 关联来源编号，`inferred` 附依据；用户明确的计划仍写「拟／计划」，不能改成正在发生。
- 每格优先放 2–4 条具体要点。保留客户是谁、买什么、谁付款、计价单位等区别信息。尽量写成「对象＋动作／结果」；收入留价格与周期，成本留驱动因素。没有材料支持时不编金额、规模、合作方或结论。
- 九格放在同一画面。保持经典空间关系，成本与收入位于底部；不画等宽的 3×3 九宫格，不擅自换成 Lean Canvas。颜色服务于分区与客户对应，推测同时用文字标签，不能只靠颜色辨别。

## 生成与验收

在唯一临时目录准备输入 JSON，结构见 [Tools/Render.help.md](Tools/Render.help.md)，完整虚构示例见 [Example.json](Example.json)，版式参考见 [Example.png](Example.png)。将本技能真实目录记为 `SKILL_DIR`，从任意工作目录运行：

```sh
bun "$SKILL_DIR/Tools/Render.ts" --input "$WORK_DIR/model.json" --output "$WORK_DIR/model.html"
```

| 用户意图 | 参数或行为 |
|---|---|
| 默认画卡片 | 默认宽度 1600 CSS px；最终导出 PNG |
| 指定宽度 | `--width 1200` 至 `--width 2400`；仍需检查可读性 |
| 保存到指定位置 | 验收后把最终 PNG、HTML、JSON 放到该目录 |

使用本机真实浏览器打开 HTML，等待字体就绪，检查九格顺序、全部文本与溢出。当前环境有 Interceptor 时按其隔离与截图合同执行；其他环境用可用的真实浏览器工具。`window.businessModelAudit()` 提供块数、缺项、推测和几何溢出检查。导出整个 `#canvas` 为 PNG，推荐 2 倍像素；没有截图能力时保留 HTML 并明确 PNG 未完成，不能把 HTML 链接充作图片。

打开最终 PNG 看全图，再放大密集区域检查。若文字过密，先精简重复表述或增高画布；保留关键条件，禁止裁切、隐藏超出内容或缩字硬塞。渲染器拒绝过长／过多条目时，整理输入后重跑，不绕过校验。

最终在对话直接展示 PNG，给出 HTML 和 JSON 的文件链接；简短指出影响理解的待补充信息。所有草稿与截图留在临时目录，只有已验收产物进入交付目录。

## Gotchas

- 客户细分是服务对象；付费方可能与使用者不同。多边平台需在价值、渠道、收入中保留对应关系。
- 渠道描述获客、成交、交付路径；客户关系描述如何建立与维系互动。资源是拥有／可调用的东西，业务是反复做的事，伙伴是外部参与者。
- 收入来源是如何收费，融资不是收入；成本结构是支出逻辑，不能凭此推算利润或把未标周期的数据相加。
- 归类清楚不代表商业模式已成立。相互矛盾的材料、未验证需求与缺失付费逻辑应留痕，不能用顺滑的总结抹掉。
- 页脚保留 Business Model Canvas、Strategyzer.com 与 CC BY-SA 3.0 归属；此处是中文改编排版，不是官方原版或对原书全文的复述。许可适用于画布模板，用户业务材料的权利不因此改变。

## Examples

- 「ljg-business-model：我们为小餐馆提供采购服务，按成交额收费……」→ 用已有资料画一张卡；缺失伙伴和成本写待补充。
- 「把这份双边平台访谈做成商业模式画布」→ 使用者与付费方分别标记，追踪各自价值和收入路径。
- 「这是昨天的画布，现在改为年费订阅」→ 更新收费方式，并依据补充材料检查客户关系和成本是否也变化；无证据的变化标为推测。
